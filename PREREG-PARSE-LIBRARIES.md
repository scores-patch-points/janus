# PREREG: does a neural parsing LIBRARY add to what our own parsers do, as a codec source and as a second eye? (frozen before anything is installed, downloaded or scored; nothing run)
Written 2026-11-20 by the Janus session at its user's direction ("are we leaving parsing libraries on the table?", then "try it"). Builds on PREREG-PARSE-ENGLISH-LAYERS (stamp 1738c67947740fc3: our frozen arms POOL, BLEND, EWT, GUM, the same metrics and bootstrap) and DESIGN-COMPUTED-CODEC.md (a library enters as a codec SOURCE with a named giver, scope, hash and standing candidate, revisable by replacing its entry). Stamp: sha256 first 16 hex in PREREG-PARSE-LIBRARIES.md.sha256short.

## 1. What is checked, and what it shows (read 2026-11-20, nothing downloaded)
- Nothing parsing-related is installed here: no spaCy, Stanza or UDPipe in either Python, no parser weights in the Hugging Face cache (torch 2.15.0 and transformers 5.23.0 are in the embedder venv).
- Stanza 1.15.1 (PyPI; Apache-2.0; wheel 2.18 MB). `pip install --dry-run stanza` into the embedder venv would add only: certifi, charset-normalizer, colorama, emoji, orjson, platformdirs, protobuf, requests, stanza, termcolor, udapi, udtools, urllib3 (torch is already present). Reversible by `pip uninstall`.
- Stanza English models (Hugging Face stanfordnlp/stanza-en; card licence apache-2.0): pos/combined_charlm.pt 38.8 MB, depparse/combined_charlm.pt 142.4 MB, lemma/combined_charlm.pt 34.7 MB; pretrain/conll17.pt 106.7 MB; forward and backward charlm/1billion.pt 22.7 MB each; the default bundle default.zip 528.0 MB. The electra-large variants need a separate 1.3 GB transformer and are NOT used here.
- TRAINING DATA, from Stanza's own page (stanfordnlp.github.io/stanza/combined_models.html): the English combined models are trained on UD EWT, GUM, GUMReddit, PUD and Pronouns, with the SPECIALIST lexicon for lemmas. Consequences: (a) PUD is NOT a fresh test for Stanza; (b) EWT and GUM dev and test are POSSIBLY contaminated (a release or split difference could put a sentence of our files into its training); (c) its weights are derived from data that includes non-commercial GUM: research use, vendored locally, never committed.
- Fresh held-out sets that neither Stanza nor our parsers saw: UD_English-LinES test (1,251,748 bytes; a different annotation scheme in xpos and features, which both families face equally; licence to be confirmed from the treebank before use) and UD_English-ParTUT test (188,161 bytes; CC BY-NC-SA 4.0: numbers only, nothing committed). UD_English-PUD test (1,415,384 bytes; CC BY-SA 3.0) is fresh for OUR parsers only and is reported as such.

## 2. Arms (the same evaluation as the parent: GOLD tokenization handed in (Stanza's `tokenize_pretokenized`), UPOS, UAS, LAS, punctuation excluded, document bootstrap by document, 2,000 resamples, seed 20261119, a difference counts at 0.5 LAS points with an interval above 0)
POOL and BLEND (frozen, trained on EWT and GUM train only); STANZA = pos + depparse of the combined_charlm package, its own tagger's UPOS fed to its own parser; ENS_LIB = per sentence the analysis among {POOL, BLEND, STANZA} that agrees most with the other two (minimum Bayes risk, ties to STANZA); SEL = STANZA where it disagrees with POOL, else POOL, is NOT an arm (a disagreement is evidence, never an automatic override).

## 3. Sets and labels
FRESH for all arms: LinES test, ParTUT test (read once each). OURS-ONLY fresh: PUD test. DEV (debugging): EWT dev and GUM dev; the library arms on EWT and GUM TEST are labelled REUSED and POSSIBLY CONTAMINATED for Stanza and are not primary. The frozen TEST read of EWT and GUM test for our own arms is separate and already pre-registered.

## 4. Falsifiers, written first
- L1: STANZA's LAS does not exceed POOL's on LinES test AND on ParTUT test by at least 0.5 points with a bootstrap interval above 0 (the library adds nothing on text no one trained on).
- L2: over all tokens of the fresh sets, POOL's error rate where STANZA disagrees with it on (head, relation) is less than twice POOL's error rate where they agree (a disagreement carries no signal about our errors: the library is not an independent eye). 2 is an ARBITRARY CONSTANT of ours, labelled; the rates are reported with their counts.
- L3: ENS_LIB does not beat the better of POOL and STANZA on the fresh sets by 0.5 points (the layers add nothing beyond the best parser).
- Reported, no gate: STANZA's UPOS and UAS; STANZA on EWT and GUM dev and test (flagged); wall-clock seconds per 1,000 sentences and disk for each arm; the sentences where POOL and STANZA disagree most, as a list for Penelope.
- Reading rule: a library earns a place as a codec source (an entry with its giver, versions, file hashes, licence caveats and standing candidate) only if L1 is NOT hit; it earns a place as a SECOND EYE only if L2 is NOT hit; layering earns its place only if L3 is NOT hit. A hit names which of those it is not. No claim beyond English, standard-ish text and these treebanks; creoles and non-standard English remain a typed gap unless a library ships a model for them, which is checked separately and not assumed.

## 5. Limits and rules this follows
Rule 11: the library receives gold-tokenized forms (it is evaluated as a parser, not as a tokenizer); the clitic split question is separate. Rule 14: nothing is written to any log by this evaluation; adoption as a codec source is an entry written through the door and judged by Penelope, with the library's own claims about its training data recorded as the giver's statement, not as ours. A model never judges: a library parse is a reading with a source. Downloads and the install need the owner's word with their sources and sizes named (the list is in the message that accompanies this file).
